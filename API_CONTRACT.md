# Folio ↔ FolioImageWorker: API v1

Воркер работает на ПК и **сам** обращается к публичному HTTPS-адресу Folio. Folio никогда не подключается к адресу ПК. Полную ссылку для `FOLIO_POLL_URL` показывает Folio → Настройки → Воркер изображений. Каждый GET/POST к Core содержит `Authorization: Bearer <WORKER_API_KEY>`, `X-Folio-Worker-Id: <постоянный UUID установки>` и `X-Folio-Session-Id: <UUID текущего процесса>`. ID установки хранится рядом с рабочей базой и исходниками; новая сессия создаётся при запуске.

## 1. Получение задания

`GET https://<folio>/folio/image-worker/next`

- `204 No Content`: очередь пуста.
- `200 OK`: одно действие `generate` или `place_print_files`. Повторное получение генерации с теми же `worker_id` и `id` не запускает новый платный запрос: состояние хранится в SQLite.
- `401`: неправильный ключ.
- `422`: неверные UUID заголовков.

```json
{
  "action": "generate",
  "id": 123,
  "worker_id": "924539a0-d73e-4d62-a16d-2d35ce91a2cf",
  "prompt": "Заменить фон",
  "model": "seedream-5-0-lite",
  "width_cm": 40,
  "height_cm": 60,
  "image_urls": [
    "https://one.customcraft-mes.ru/folio/image-worker/input/<token>/0"
  ]
}
```

`image_urls` содержит 1–8 изображений в порядке брифа. Folio выдаёт ссылки со случайным токеном; отдельная авторизация для скачивания фото не нужна. Воркер скачивает и проверяет изображения, затем передаёт их локальные копии AI Tunnel в `input_references` как `data:image/png;base64,...`. Внешнему провайдеру не требуется скачивать изображения с Folio; ссылки с токенами ему не передаются.

`offer_id` и `order_number` — артикул товара и номер заказа Ozon для подписей на печатном файле. Пустое или отсутствующее поле означает, что соответствующей подписи не будет. На предпросмотр подписи не наносятся.

`skip_generation: true` означает, что Folio счёл фото достаточным для печати: воркер не вызывает провайдера и собирает `preview.jpg` и печатный файл из первого исходника, статус `generating` не отправляется. Отсутствие поля равно `false`.

`model` фиксируется при постановке задания в очередь. Бюджетные профили: `seedream-5-0-lite` (4K), `seedream-4.5` (4K), `seedream-5-0-flash` (2K), `hy-image-v3.5-preview` (4K), `flux-3-image-klein` (4K, соотношения сторон включая 5:7 и 7:5). Все принимают до 8 исходников Folio. Если поля нет в старом задании, используется HY Image. Старые `flux-3-image`, `gemini-nano-banana-2.1`, `seedream-5-0-pro` распознаются для совместимости, но новая платная генерация блокируется: модели не укладываются в выбранный бюджет. Существующий готовый файл можно использовать без повторной генерации. Воркер сообщает поддержку выбора модели заголовком `X-Folio-Image-Models: 1` и провайдер заголовком `X-Folio-Image-Provider: aitunnel` (или `mock`). Перед выбором новых моделей необходимо обновить воркер; общий флаг версии 1 сам по себе не подтверждает поддержку новых названий старым воркером.

## 2. Состояние и результат

### Подготовка промпта (13.10.2026)

Задание может содержать `prompt_mode`: `direct` (старое поведение, значение для
заданий без поля) или `vision`. Core фиксирует режим при постановке в очередь,
из настройки UI «Подготовка промпта». Старые задания не мигрируются.
Воркер объявляет `X-Folio-Prompt-Planner: 1`; Core не выдаёт vision-задание старому
воркеру. Vision поддерживается в pull-подключении с AI Tunnel.

В режиме vision Gemini 2.5 Flash Lite получает исходные фото, инструкцию и размер
через `/chat/completions`. Итоговая инструкция до 3500 символов сохраняется в
`prompt-plan.json` с отпечатком входных данных и фактической стоимостью.
Системная инструкция LLM восстановлена из исходного сравнительного теста и
дополнена сохранением позы, поворота головы и ракурса. Генератор получает исходные
фото и ответ LLM без дополнительного длинного блока ограничений.
Промпты и изображения не выводятся в журналы. Используется существующий ключ AI Tunnel.
После потери ответа LLM или перезапуска с отметкой запроса без результата — unknown,
без автоматической повторной оплаты. Ошибка/обрезанный ответ LLM не запускает
генерацию. При наличии сохранённого результата LLM повторно не вызывается.
Новый режим не меняет превью и печатные поля.


`POST https://<folio>/folio/image-worker/jobs/{id}` с `multipart/form-data` и тем же Bearer-ключом:

| Поле | Значение |
| --- | --- |
| `worker_id` | UUID из задания |
| `status` | `queued`, `generating`, `composing`, `completed`, `failed` или `unknown` (результат платного запроса не подтверждён) |
| `print_file` | Полный локальный путь к исходному JPG в рабочей папке, обязателен при `completed` |
| `error` | Короткая причина ошибки при `failed` или `unknown` |
| `preview` | JPEG-файл, обязателен при `completed`; наибольшая сторона ровно 1000 px, до 10 МиБ |

Успешный ответ: `200 {"ok":true}`. Повторение того же завершённого результата безопасно. Folio сохраняет JPEG в своём хранилище и даёт блоку сценария **«Отправить макет»** отправить его покупателю через Ozon. Статус `completed` означает готовность источника и превью, но не размещение файла в производстве.

Очередь выполняет одно задание за раз. Воркер повторяет запрос к Folio каждые несколько секунд, а отправку статуса после временной сетевой ошибки повторяет до подтверждения. Счётчик и время следующей попытки доставки хранятся отдельно для каждого задания, поэтому сбой одного результата не блокирует остальные. Ответы `409 image_worker_result_conflict` и `404 image_worker_job_unknown` останавливают доставку только устаревшего состояния этого задания; ошибка остаётся в БД и журнале, успешная доставка не имитируется. Folio не опрашивает воркер.

## Обработка и файлы

Для новых заданий `IMAGE_PROVIDER=aitunnel` воркер вызывает `POST /v1/images/generations` на основном или резервном официальном хосте AI Tunnel с зафиксированной моделью задания, 1–8 референсами, инструкцией, поддерживаемым для модели разрешением и ближайшим соотношением сторон. AI Tunnel возвращает готовое изображение синхронно в `data[0].b64_json`; опроса внешней задачи и callback нет. Старые задания Nano Banana сохраняют свой провайдер в SQLite и завершаются по прежнему API.

Перед платным запросом воркер сохраняет в SQLite отметку о начале отправки. При ошибке подключения до отправки запроса он переключается с `api.aitunnel.ru` на `ru-api.aitunnel.ru`. По заданному для этой интеграции правилу HTTP 504 не списывает оплату: воркер повторяет запрос до трёх попыток, переключаясь на зеркало после первой. После трёх ответов 504 задание завершается ошибкой. Если получен другой HTTP 5xx, ответ потерян или процесс перезапущен до сохранения изображения, статус становится `unknown`: воркер **не повторяет** платный POST автоматически, а Folio не продолжает сценарий. Результат и возможное списание следует проверить вручную. Баланс аккаунта и кэшируемая статистика ключа не связывают расход с конкретным заданием, поэтому не служат разрешением на повтор. Без `AITUNNEL_API_KEY` в режиме `aitunnel` новые задания из Folio не забираются. Превью и печатный JPG собираются локально после получения результата.

После генерации воркер сразу собирает макет из полученного изображения. `width_cm` и `height_cm` задают **видимую часть картины**, а не размер всего печатного листа. Её размер в пикселях — `round(cm / 2.54 × 150)` по каждой стороне. Превью показывает только эту часть и не меняется из-за полей.

Печатный JPG содержит видимую часть, затем зеркальное продолжение изображения со всех четырёх сторон, затем белое поле со всех четырёх сторон. Ширина каждого поля зависит от большей стороны видимой части:

| Большая сторона | Зеркало с каждой стороны | Белое поле с каждой стороны |
| --- | ---: | ---: |
| До 60 см включительно | 2,5 см | 3,5 см |
| Свыше 60 до 90 см включительно | 4,5 см | 5 см |
| Свыше 90 см | 4,5 см | 7 см |

На верхней белой полосе, в 0,5 см от края листа, по центру печатается `Артикул: <offer_id>`, на нижней, так же в 0,5 см от края, — `Заказ Ozon: <order_number>`. Высота шрифта — 0,5 см (около 14 pt). Если подпись длиннее ширины листа, шрифт уменьшается, текст не обрезается.

Например, для видимой части 40×60 см зеркало даёт 45×65 см, а JPG с белыми полями — **52×72 см**. Общий размер JPG вычисляется как `round((видимая сторона + 2 × (зеркало + белое поле)) / 2.54 × 150)` пикселей; из-за округления поля с противоположных сторон могут различаться на один пиксель. Метаданные JPG остаются 150 DPI. В рабочей папке `data/<worker_id>/` остаются оригиналы Ozon, нормализованные входные изображения, `generated.png`, `preview.jpg` и исходный `print.jpg`. После размещения источник автоматически не удаляется.

## 3. Размещение после MES

Core выдаёт действие через тот же `GET /folio/image-worker/next` только установке, выполнившей генерацию:

```json
{"action":"place_print_files","id":123,"worker_id":"924539a0-d73e-4d62-a16d-2d35ce91a2cf","worker_instance_id":"11111111-1111-4111-8111-111111111111","layout_version":"preview-media-id","operation_id":"44444444-4444-4444-8444-444444444444","claim_token":"55555555-5555-4555-8555-555555555555","source_print_file":"D:\\Work\\data\\924539a0-d73e-4d62-a16d-2d35ce91a2cf\\print.jpg","destination":{"kind":"worker_print_directory"},"print_files":[{"serial":1,"instance_code":"copy-1","layout_key":"art-1","filename":"art-1.png"}],"pending_serials":[1]}
```

`destination.kind=worker_print_directory` означает выбранную в приложении производственную папку (`PRINT_SHARE_PATH`). Имена из `print_files` используются без изменений. Проверяются имя, версия, операция и владелец; путь из Core не задаётся. Для другого расширения воркер кодирует нужный формат с 150 DPI. Публикация атомарна, существующий чужой файл не перезаписывается. В SQLite остаются манифест с путями/хешами и очередь отчётов. Повторное действие сверяется с ними, а после частичного успеха обрабатываются только `pending_serials`.

Перед записью воркер подтверждает захват повторным GET; при потере lease запись останавливается. Отчёт отправляется на тот же `POST /folio/image-worker/jobs/{id}` как `application/json`:

```json
{"action":"place_print_files","operation_id":"44444444-4444-4444-8444-444444444444","layout_version":"preview-media-id","claim_token":"55555555-5555-4555-8555-555555555555","status":"finished","files":[{"serial":1,"filename":"art-1.png","status":"completed","saved_path":"D:\\Prints\\art-1.png","size_bytes":123456,"sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"}]}
```

При ошибке файла используется `status=failed` и непустой `error`. Сетевой сбой доставки повторяет тот же сохранённый отчёт, не копирует файл заново. При 409 старый захват отвергается и воркер снова опрашивает Core. Несколько частей отчёта передаются со статусом `running`, завершающая — `finished` (лимит Core 64 KiB). Успешное размещение всех имён подтверждает только ответ Core после фактической записи.

`GET /health` и `POST /v1/jobs` доступны локально для диагностики и ручных тестов. Folio их не вызывает.

# FolioImageWorker

Windows-приложение получает задания из Folio, редактирует 1–8 исходных изображений через AI Tunnel, создаёт печатный JPG 150 DPI и превью JPEG (1000 px по длинной стороне). Folio получает статус и превью через исходящее соединение воркера. [Контракт API](API_CONTRACT.md).

## Сборка и запуск без Docker

1. Запустите `Build Windows.cmd` на ПК с Python 3.14 и интернетом. Готовая программа: `dist\FolioImageWorker\FolioImageWorker.exe`. Переносить нужно всю папку `dist\FolioImageWorker`. На ПК для запуска не нужны Python и Docker.
2. Откройте EXE или `Start Worker.cmd`. При первом запуске укажите ссылку опроса из настроек Folio, общий ключ Folio/воркера, ключ AI Tunnel и **две папки**. Рабочая папка хранит исходные изображения Ozon, результаты генерации, превью, печатный источник, очередь и логи; она должна быть локальной. Производственная папка может быть локальной (`D:\Prints`) или сетевой (`\\server\share`). Вставленный путь вида `//server/share` приводится к Windows-форме автоматически. Сетевой путь должен открываться в Проводнике под той же учётной записью Windows, под которой запущена программа.
3. Приложение проверяет запись в обе папки при сохранении настроек. Печатный источник остаётся в рабочей папке до подтверждённого размещения; автоматически он пока не удаляется.

Настройки: `%LOCALAPPDATA%\FolioImageWorker\config.json`. Файлы задания: `<рабочая папка>\data\<id задания>\` (`source-1.jpg/png/webp`, `generated.png`, `preview.jpg`, `print.jpg`). Постоянный ID установки лежит в `<рабочая папка>\worker-installation-id`, журнал заданий и размещения — в `<рабочая папка>\data\jobs.sqlite3`. Их нужно хранить вместе с исходниками: перенос только ID на другой ПК без этих файлов нарушит повторное размещение. Лог: `<рабочая папка>\logs\worker.log`, также виден в окне. В программе есть кнопки запуска, остановки, настроек, открытия обеих папок и включения/выключения автозапуска. Автозапуск включается только по нажатию кнопки и действует для текущего пользователя Windows; при входе в систему открывается приложение и запускается воркер. `Stop Worker.cmd` тоже останавливает сервис.

Если рядом с программой найден старый проект с `.env` и `data\jobs.sqlite3`, приложение подставит прежние настройки и рабочую папку. При старте оно остановит старый Docker-контейнер, чтобы задания не забирали два воркера одновременно.

Для теста без оплаты выберите режим `mock`: он копирует первое входное изображение вместо редактирования через AI Tunnel. Результат этого режима не предназначен для заказа клиента.

## Обработка

Воркер опрашивает Folio и получает выбранную в Folio модель AI Tunnel, изображения, описание и размеры в сантиметрах. Из результата он собирает JPG 150 DPI: видимая часть заданного размера, зеркальные края и белые поля. Превью показывает только видимую часть. Печатный JPG остаётся в рабочей папке. После согласования и принятия заказа MES Core выдаёт тому же воркеру отдельное действие размещения с точными именами файлов. Воркер записывает каждый экземпляр в производственную папку и отправляет Core результат. При ином расширении файл перекодируется в указанный формат. Повтор действия сверяется с локальным журналом и SHA-256; чужой файл не перезаписывается. Задания обрабатываются по одному.

Если AI Tunnel недоступен до отправки платного запроса, соединение повторяется и при необходимости используется официальный резервный адрес. HTTP 504 повторяется до трёх раз. При неопределённом исходе платного запроса задание получает статус `unknown` и автоматически не отправляется повторно. Ошибки опроса Folio и доставки результата повторяются с задержкой.

Старые задания Nano Banana сохраняют прежний провайдер в базе и могут быть завершены после миграции. Новые задания используют выбранную модель AI Tunnel.

Исходный код также можно запускать через Docker. Для записи в UNC-папку удобнее Windows-сборка: учётная запись приложения должна иметь доступ к ней.
